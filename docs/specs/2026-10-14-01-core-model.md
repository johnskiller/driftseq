# DriftSeq 核心数据模型 (01)

**日期**: 2026-10-14 · **状态**: draft → review
**前置**: `2026-10-14-00-master.md`（定位）· 本文解决 00 的待定项：loop 上限、swing 归属、条件库、pattern 存储

## 1. 时间模型

- **音源 of truth**: 引擎从音频渲染回调 tick（44100 Hz，64-frame block，melodee/Polly 惯例），
  精度 = sub-block；MIDI 事件在 tick 边界发出，字节流确定性（测试契约见 §7）
- **全局 transport**: BPM（4 分音符基准，内部 24 PPQ 对外发 MIDI clock）、start/stop、global swing
- **步长单位**: 每轨独立 division：`1/8, 1/8T, 1/16, 1/16T, 1/32`（对齐 SQ-64 的 TRIPLETS/RESYNC 能力）
- **loop 长度**: 每轨独立，**1–64 步**（v1 上限 64，见 §6 待定）；**loop 窗口 = [loop_start, +loop_len) mod 64**
  ——起点同样 per-track（SQ-64 的 RANGE、melodee 的 first/len 同语义）：12 步 bass 可以骑在 64 步小节的
  第 5 步起。窗口外 step 仍可编辑（不响，除非窗口覆盖）；跨 division 统一换算到 16 分网格计数，
  相位漂移来自"不同长度 + 不同起点 + 不同 division 同时循环"

## 2. Track 模型

```c
#define DS_TRACKS   16
#define DS_STEPS    64          /* v1: loop 上限 64 步 */
#define DS_VOICES   4           /* 每 step 最多 4 个同时音（和弦） */

typedef struct {
    uint8_t note;               /* 0–127, 0xFF = 空 */
    uint8_t vel;                /* 1–127 */
    uint8_t gate;               /* gate 长度，单位 = 本轨 step；0xFF = 到下一事件或 loop 尾 */
} ds_note;

typedef struct {
    ds_note  v[DS_VOICES];
    uint8_t  prob;              /* 0(=OFF)–100, 默认 100；0 = step 静默保留 */
    uint8_t  cond;              /* ds_cond 枚举，见 §4 */
} ds_step;

typedef struct {
    ds_step  steps[DS_STEPS];
    uint8_t  division;          /* 枚举 §1 */
    uint8_t  loop_start;        /* 0–63：loop 窗口起点（SQ-64 RANGE 语义）；窗口 = [start, start+len) mod 64 */
    uint8_t  loop_len;          /* 1–64 */
    uint8_t  channel;           /* 1–16 (MIDI out) */
    uint8_t  route;             /* USB / GM / BOTH */
    uint8_t  bank, prog;        /* 选轨时发 PC */
    uint8_t  mute;
    uint8_t  swing_amt;         /* 0–100，全局 swing 的应用比例 */
    uint8_t  voice_mode;        /* 0=POLY 1=MONO(legato, 取最高音)——对应黑键 MONO/POLY 丝印 */
    /* 生成器 meta（可选）：euclid {on,k,n,rot}，见 §4 */
    uint8_t  eu_on, eu_k, eu_n, eu_rot;
} ds_track;
```

**RAM 账**：step = 4×3 + 2 = 14 B；track = 64×14 + meta ≈ 913 B；16 轨 = **14.4 KB / pattern**。
16 patterns 全驻 RAM = 230 KB > 预算 → **RAM 只驻 1 个编辑 pattern（14.4 KB）+ 全部 16 个 pattern 驻 flash
（运行时换入换出，链切时预取下一 pattern）**。flash 账：16×14.4 KB ≈ 230 KB，放独立分区（melodee flash-map
v2 的教训：先画 map 再写存储层）。

## 3. Pattern 与 Chain

- **pattern = 16 条 ds_track 的快照**（内容+meta）。内容永远按轨编辑；pattern 层只有 copy / clear / chain
- **chain**: 有序表 `{pattern_idx, repeat}`（≤64 项），即简化版 song。切换语义（关键决策，live 用）：
  **默认热切**——transport 不断，每轨**保持自己的 loop 相位**，只是内容换新 pattern 的对应轨；
  可选 cold（全轨回 step 0）。热切是"看见漂移"体验的延续：链上不同 pattern 的轨长不同，漂移会自然演化
- **fill**: 全局 FILL 按钮置一个一次性 flag，条件为 FILL 的 step 在下一圈生效一次（对齐鼓机惯例）

## 4. 生成层（对齐 SQ-64 并超出）

- **Euclid**: 每轨 meta `{on, k, n, rot}`，Bjorklund 算法（Toussaint 读法，CTL-1 同源）。开 = steps 由
  生成器重算（只铺 note，velocity 用 track 默认）；手改 step 后 meta 自动标记 detached（再拧参数按新 meta
  重铺并覆盖——文档写明）。v1 只铺鼓 lane 语义（单音），旋律轨可用但同规则
- **probability**: 每 step 0–100%，RNG 种子化（确定性重放）
- **conditions**（v1 枚举，`ds_cond`）:

| 值 | 语义 | 对标 |
|---|---|---|
| 0 | 无条件 | |
| 1–6 | 每 N 圈触发一次 (N=2..7) | SQ-64 ALTERN |
| 7 | 仅 chain 本 pattern 的第 1 圈 | intro |
| 8 | 仅最后 4 圈 | fill-out |
| 9 | FILL flag 置位时 | 手动 fill |
| 10 | 前一 step 触发时才触发（flam/连带） | 条件联动，SQ-64 无 |

## 5. MIDI 路由

- **每轨**: channel + route(USB/GM/BOTH) + bank/prog；轨静音 = 本轨不发（GM 侧同步 all-notes-off）
- **transport**: clock/start/stop 恒从 USB out（master 角色）；MIDI clock in = follower 模式（slaving，
  v1 可后置）
- **MIDI in**: 默认并入 GM 模块（模块模式，白送）；REC armed 时作为实时录输入源

## 6. 待 John 拍板

1. loop 上限 64 步（存储 229 KB/16 patterns）vs 128 步（458 KB，flash 紧）——建议 **64**
2. 每 step 4 voices 够否（和弦 3–4 音 + bass 单音场景够；弦乐堆叠需事件列表制，成本高）——建议 **4**
3. chain 热切默认（相位保持）——建议 **是**，cold 做成 per-chain 选项
4. condition 枚举 v1 收这 10 个？——建议**是**，11+ 走 v1.1
5. swing 全局量 × per-track 比例——建议**是**（纯 per-track 独立 swing 会破坏 groove 一致性）

## 7. 测试契约（host 阶段就锁死）

- 引擎纯 C：`drift_tick(state, in) -> bytes[]`，RNG 种子化，无全局隐藏状态
- 场景脚本（借 ctl_host 的 `*.ctl` 模式）→ 断言两样：**MIDI 字节流 golden hash** + **屏幕 PNG hash**
- 任何引擎改动跑全场景，hash 变化必须在 diff 里可解释
