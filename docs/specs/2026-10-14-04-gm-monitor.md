# DriftSeq GM 监听设计 (04)

**日期**: 2026-10-14 · **状态**: draft → review
**前置**: 00（GM 监听支柱）、01（track.route / channel / bank-prog）
**配方源**: Polly v0.4.1（`firmware/src/dsp/eas/`，已验证上机出声）——EAS 集成整体搬，Apache-2.0

## 1. 为什么用 EAS（两次验证）

- Polly（QY70 编曲机）+ CTL-1（控制器+GM）都跑 Sonivox EAS，同一块 JieLi 芯片实时出声——
  可行性已证两次，DriftSeq 只是第三个消费者
- 纯 C 固定点、**无文件系统**（live MIDI only）、wasm 可编（emu 里也有声）
- 音色 = 手机级 GM：鼓组不错，旋律偏电子琴味——**定位就是"草稿监听"**，正式出声走 MPC，不装腔

队列，不读文件）；chorus/reverb 保留（EAS 内置，开销小，GM 质感需要）；只保留 wavetable 引擎，FM/DLS
引擎按 EAS 配置关掉。

## 3. 接线：loopback（关键设计）

**EAS 的 MIDI parser 吃与 USB OUT 完全相同的字节流**——

```
        ds_track 引擎 tick
              │
        产生 MIDI 事件 (note/CC/PC/bend, per-channel)
              │
     ┌────────┴─────────┐
     │ route=USB/BOTH   │ route=GM/BOTH
     ▼                  ▼
  USB MIDI OUT      EAS parser (MIDI 队列)
  (→ MPC/桌面)       │
                     ▼
              EAS 渲染 (audio ISR, 44100)
                     │
                     ▼
              UAC / 耳机
```

- **同一股字节**喂两路 → "耳机草稿" ≡ "MPC 出声"，PC/CC/bend 行为零分歧（支柱的落地机制）
- 引擎只发一次字节，router 按 `route` 字段复制分流（USB-only 轨不进 EAS，省 CPU）
- EAS 的 16 个 MIDI channel 与 DriftSeq 的 16 轨 1:1 对齐（track.channel = EAS channel）

## 4. 资源账（对照 01 的 flash/RAM）

- **flash**: 采样 212,050 B const + EAS 核心编译后 ~30–50 KB 代码 → 独立分区
  - Polly v0.4.1 整包 = 609,929 B 就塞下了 UI + EAS + bank + 编曲器 → DriftSeq（无编曲器、有 16 轨 seq）
    同 slot 放得下；**GM 关闭的纯 MIDI build 也保留**（`MELODEE_`-style 编译 flag `DRIFTSEQ_GM`，
    关掉省 212 KB flash 给更多 pattern 槽）
- **RAM**: 96 KiB EAS pool 放 `.pool`（336 KiB POOL 段占 28%）；纯排序器状态下绰绰有余
- **CPU**: EAS ≈ 8 复音实时渲染，Polly/CTL-1 双背书；16 轨 MIDI 事件生成本身是纯字节操作，轻

## 5. 白送：MIDI-in → GM 模块模式

- DriftSeq 的 USB MIDI IN 接到 EAS 同一条 parser 路径 → FM-1 变成一个 **16 部分 GM 音源模块**
- 接 MIDI 键盘 / DAW，独立弹奏 GM，不占 DriftSeq 的 seq——**零额外工作量**（同一路径复用）
- 这是 Polly/CTL-1 都有、但 DriftSeq 因为"本来就要接 EAS"而免费拿到的能力

## 6. 音色浏览（UI 接入，见 03 §2/§3 的 ROUTE/bank-prog）

- 每轨 `bank, prog` → 切轨发 PC；ROUTE=GM/BOTH 时 EAS 用对应 program
- 128-program 浏览：SEL 长按 / PRESETS 键 → GM 名列表（const 表 128 个 GM program name，~4 KB）
- 鼓轨约定：channel 10 = GM 打击乐（EAS 的 ch10 drum set），黑键 pitch 排 = 鼓映射（02 §2.1）

## 8. 测试契约增量

- EAS 是黑盒（Apache-2.0，不重测内部），只测**接缝**：
  - router 分流：`route=USB` 轨的字节不进 EAS 队列（断言队列字节）；`route=BOTH` 两路都收
  - loopback 等价：同一 pattern，GM-only vs USB-only 两路，引擎产出的字节流 hash 必须相等
    （证明"分流不分叉"——这是支柱的测试保证）
- EAS 出声 = 上机听（host 无音频，host 阶段只验字节接缝 + pool 峰值 `eas_pool_peak()` < 96 KiB）
